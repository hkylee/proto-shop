## 공통 질문

세 안은 같은 여정(상품 상세 → 요금제 → 옵션 → 신청서 → 인증 → 결제)을 놓고 **"AI Agent 가 화면을 얼마나 가져가는가"** 한 축만 달리한 것이다.

| | 1안 | 2안 | 3안 |
|---|---|---|---|
| 주도권 | Static 페이지 | Agent 대화 | Agent 대화 |
| 선택 모듈이 놓이는 곳 | 페이지 컴포넌트 그대로 | 바텀 모달 | 대화 안(바닥 행·카드) |
| 개인정보 입력 | 페이지 밖 주문 확인 화면(신청서 미포함) | 3안과 같은 바텀시트 4장 | 바텀시트 4장 |
| Agent 호출 횟수 | 4회(일시 호출) | 상시 | 상시 |
| 스텝 수 | 6 | 15 | 16 |

세 안을 나란히 돌려 보고 답하려는 질문:
1. 고객이 **통제감**을 느끼는 지점은 어디인가 — 직접 탭 vs Agent 제안 수락.
2. 대화가 길어질 때 **"내가 뭘 골랐는지"** 가 어디까지 읽히는가.
3. **민감 정보**(주민번호·주소)는 대화 안에서 받아도 되는가, 별도 표면이 필요한가.
4. 전체 길이(스텝 수·탭 수)와 신뢰(근거 노출) 사이의 균형.

## 1안 · Static 중심 + AI Agent 일시 호출

**정의** — Agent 로 화면이 전환되지 않는다. Static 상품 상세 안에서 Agent 를 잠깐 불러 답을 듣고, 다시 페이지에서 옵션을 직접 고른다. "이 옵션으로 선택해 드릴까요?" → 동의 → Agent 가 닫히며 값이 페이지에 자동 선택.

### 고민 지점
- **답을 어디에 놓을 것인가.** 5갈래(A 답변 스트립 / B 답변 카드 / C 하단 피커 / D 상주 에이전트 바 / E 스트립 + 페이지 가리킴)를 비교. 카드(B)는 근거를 다 보여주지만 하단 1/3 을 덮고, 피커(C)는 통제감이 높지만 섹션마다 리스트를 다시 그려야 해 형식이 하나로 안 모인다. → **E 채택**: "답은 하단에, 대상은 페이지에".
- **E 안에서 추천을 어떻게 표시하나.** E-1 배지+팬 / E-2 상태형(항목 자체가 파란 추천 상태, 페이지에서 직접 탭이 동의) / E-3 섹션 캡션. E-2 는 새 UI 가 거의 없지만 "AI 가 고른 것" 이라는 표식이 남지 않고, E-3 은 컴포넌트와 무관한 자리라 범용이지만 대상과 표시가 떨어진다. → **E-1 확정**(2026-09-08). 다만 배지 자리를 카드·행·스와치 3종에 각각 정해야 하는 비용을 감수.
- **T+ 버튼이 입력창으로 바뀌는 방식.** 페이지 전환 없이 "잠깐 부른다" 는 느낌을 모핑 하나로 줘야 한다. T-1 늘어나기 / T-2 올라가서 펴지기 / T-3 CTA 와 합쳐지기 → **T-1 확정**(한 호흡).
- **선택 시점.** Agent 답이 나오는 순간 자동 선택할지, [이 항목으로 선택] 을 눌러야 선택할지. 통제감을 위해 **탭 후 선택** 으로 두되, 선택 순간 [AI 추천] 배지는 디졸브로 지운다(사용자: 배지가 남지 않게).
- **스크롤 질감.** 고정 시간 scrollTo 는 "모바일 같지 않다" → 위로는 H-3 천천히 끌기, 아래로는 D-3 손가락 없는 팬.
- **끝을 어디서 맺나.** 1안은 신청서 없이 [주문하기] → 주문 정보 확인 화면(X-1 슬라이드 인)에서 끝. CTA 라벨도 [결제하기] 가 아닌 [주문하기].

### 검증하려는 것 (스텝별)
| 스텝 | 검증 포인트 |
|---|---|
| 1 진입 | Agent 를 부르지 않은 기본 상태가 3안과 같은 페이지에서 어떻게 보이는지. T+ 가 "잠깐 부르는" 진입점으로 읽히는지 |
| 2 색상 질의 | T+ → 입력창 모핑이 전환감 없이 읽히는지. 한 단 스트립 답이 페이지 배지와 함께 충분한지. [이 항목으로 선택] 한 탭이 통제감을 주는지, 거슬리는지 |
| 3 용량 질의 | 직접 고르기와 AI 질의가 한 페이지에 순서 없이 섞여도 헷갈리지 않는지. 위로 되돌아갈 때 스트립이 대상을 가리지 않는지(자동 팬). 반복되는 모핑이 지루하지 않은지 |
| 4 요금제 질의 | 3안에서 Agent 로 넘어가던 지점을 페이지 안에서 끝낼 때 근거 한 줄이 충분한지. 큰 카드에서도 배지·테두리·스트립 조합이 유지되는지. 남은 배지들이 계속 "AI 가 고른 것" 으로 읽히는지 |
| 5 나머지·보험 | 4번째 질의가 끼어도 리듬이 깨지지 않는지. '인기' 같은 통계 근거 질문에 한 줄 답이 충분한지(보험은 설명이 더 필요할 수 있음). 비활성 [주문하기] 가 켜지는 순간이 "다 골랐다" 신호로 읽히는지 |
| 6 주문 확인 | 직접 고른 것과 T 로 고른 것이 한 화면에 섞여 정리될 때 빠짐 없이 읽히는지. Agent 를 4번만 부르고 끝나는 전체 길이가 적절한지 |

### 열린 질문
- 보험처럼 설명이 필요한 항목에서 "한 줄 답 + 배지" 형식이 버티는가.
- 신청서·인증이 1안 범위에 없다 — 1안이 채택되면 그 뒤는 어느 표면에서 처리할지 미정.

## 2안 · AI Agent 중심 + Bottom Sheet 선택

**정의** — Agent 대화가 흐름을 끌고 간다. 단, 선택 모듈은 대화 영역에 깔지 않고 바텀 모달로 올려 고른다(Claude 식). 시트가 내려가면 대화에는 고른 결과만 한 줄 남는다.

### 고민 지점
- **대화를 가볍게 유지하기.** 3안은 요금제 캐러셀·옵션 행이 대화에 그대로 쌓인다. 2안은 "안내 문장 → 모달 → 결과 한 줄" 로 대화를 얇게 만들되, 뒤로 스크롤했을 때 무엇을 골랐는지 잃지 않아야 한다. → 결과를 흰 RadioCard 한 행에서 **'질문: … / 답: …' AnswerBubble 말풍선** 으로 바꿈(2026-09-09).
- **모달 모션.** 1차 S-1(expo-out)은 첫 프레임에 절반이 와 있어 "급발진" → **R-2 느린 출발 + 긴 안착**(0.9s) 확정. 하강은 별도(X2, 닫힐 때만 `.out`). 교훈: 상승 시작 상태와 하강 끝 상태를 같은 셀렉터에 두지 않는다.
- **딤 농도.** 42% 는 대화가 죽어 보임 → A1 32 / A2 26 / A3 20 비교 → **A3 20% 확정**.
- **시트와 안내문의 관계.** 시트가 올라올 때 위 안내문이 밀리는 방식 G0~G3 비교 → **G1 함께 밀기, 간격 30px** 확정. 이어서 시트 위치 자체를 **화면 아래 20px 고정**(높이 유지, y 만 이동, SearchAi 덮음)으로 교정 — 사용자 교정 2회 ("Height 변경 아님, y 값만", "밑에서 20px 고정").
- **새 턴 앵커.** 새 턴의 생각 점은 상단(199px)에 앵커, 이전 결과 말풍선이 다음 턴 기준점.
- **안내문 길이.** 3안 문장을 그대로 쓰면 모달과 겹쳐 무거움 → Figma 134:60944 축약본으로 교체.
- **범위 결정.** 끼어든 질문(위약금) 스텝은 2안에서 제외(사용자). 요금제는 스텝 4 안에서 시트 → 전체보기 팝업 → 적용까지 한 번에. 납부는 3안의 카드·2×2 대신 **예/아니요 시트 + 번호 인증 시트**.
- **3안 재사용의 대가.** 스텝 1~3, 9~ 는 3안 스텝을 `ref` 로 빌려 씀. 스텝 8→9 에 디졸브 한 번, 대화 위쪽에 3안 이력이 보이던 문제 → `.an2-hist`(스텝 8 마지막 재현) + 3안 이력 숨김으로 정리.

### 검증하려는 것 (스텝별)
| 스텝 | 검증 포인트 |
|---|---|
| 4 이용현황·요금제 | 추천을 카드 대신 문장으로 말하고 선택을 모달 → 전체 팝업으로 넘길 때 대화가 가벼워지는지. 모달 안 [전체보기] 로 한 단계 더 들어가는 깊이가 부담스럽지 않은지. 적용 뒤 결과 한 장만 남는 것이 3안(캐러셀 유지)보다 읽기 편한지 |
| 5 SIM | 안내 → 모달 → 결과 한 줄 반복 리듬이 지루하지 않은지. 결과 한 줄만 남는 대화를 뒤로 스크롤했을 때 무엇을 골랐는지 읽히는지 |
| 6 혜택 | 모달 첫 행이 추천 항목이지만 추천 표시가 없을 때 문장만으로 어느 것을 골라야 할지 알 수 있는지 |
| 7 할인 | 한 스텝에 모달이 두 번 연속 올라올 때 피로하지 않은지. 두 모달 제목이 같을 때 헷갈리지 않는지 |
| 8 결제 방법 | 추천과 다른 항목(일시 결제)을 골라도 흐름이 그대로 이어지는지. 신청서로 넘어가는 칩이 3안과 같은 자리에 오는지 |
| 14 납부 | 3안의 납부 카드·요금안내서 2×2 대신 예/아니요 시트 + 번호 인증 시트가 더 짧게 느껴지는지. 시트 안에서 장이 바뀌는 리듬이 신청서 시트(1/4~4/4)와 같은 언어로 읽히는지 |

### 열린 질문
- 결과 말풍선만 남는 대화가 **요약** 역할까지 하는가, 별도 요약 카드가 필요한가.
- 모달이 SearchAi 를 덮는 동안 고객이 끼어들 수 없는데, 그 제약이 2안 컨셉과 맞는가.

## 3안 · 현재 방향 + 개인정보 입력 분리

**정의** — Agent 안에서 업무를 끝내는 현재 방식을 유지한다. 단, 주민등록번호·주소 등 개인정보는 대화 카드가 아니라 바텀시트로 따로 받는다.

### 고민 지점
- **추천을 먼저 내놓지 않기.** 이용현황(내 정보 조회)을 먼저 보여준 뒤 추천 → 신뢰 순서 검증. Opening 타이틀은 **고객 정보를 조회하는 턴에만**(이용현황·위약금), 안내만 하는 턴은 N-2 생각 점.
- **선택 모듈의 형태.** AiAgentCard 안에 담던 요금제·혜택·할인 행을 **카드 없이 바닥에 깐 흰 행(F-2 캐스케이드)** 으로 바꿈. 위약금 kv 카드만 카드 유지(내 정보 조회).
- **미리 선택하지 않기.** 추천을 선택 상태로 깔아 두지 않고 문장이 추천을 말한 뒤 고객이 탭 → 통제감·속도 검증. [추천] 배지는 붙였다가 제거(문장으로 충분).
- **개인정보를 어디서 받나.** 대화 안 입력 카드 3갈래(I1 키패드 / I2 Agent 자동 채움 / I3 SearchAi 입력)와 키패드 관계(K1~K3) 를 만들어 봤으나, 결국 **화면을 덮는 AI 바텀시트 4장**(주민번호 → 주소 → 이메일 → 연락번호, n/4 페이저)으로 교체. 시트 높이가 장마다 달라 윗선이 튀는 문제 → H-1 높이 트윈 + M-3 두 박자 확정. 시트는 신청서 스텝부터 하단 10px 만 걸쳐 대기(peek).
- **[다음] 을 키패드 올린 채 누를 수 있게.** 사용자: "꼭 닫히고 눌려야 돼?" → 키패드 열린 상태로 탭, 그 뒤 0.3s 하강 후 장 교체.
- **끼어든 질문.** 요금제 적용 직후 위약금 질문 → 답 → 이어서 옵션 안내로 복귀. 원래 있던 할인 방법·요금제 재선택 스텝은 요금제 카드가 할인을 이미 품고 있어 폐기.
- **되돌아가 고치기.** 대화가 길어진 뒤 쿠폰을 재선택하는 동선(위로 H-3 끌기 → 탭 → K2 칩 탭 → 아래로). 스크롤은 재선택을 빼면 항상 아래로만.
- **앱 밖 인증·결제.** 토스로 나갔다 돌아오는 방식 X1 슬라이드 / X2 시트 안 / X3 페이드+배너 → X1. 완료 선 그리기 D1/D2/D3 → D2 순차. 결제는 대화 안에서 끝낼 수 없어 외부 화면으로 넘기고 손을 놓는다.

### 검증하려는 것 (스텝별)
| 스텝 | 검증 포인트 |
|---|---|
| 1 상품 상세 | 첫 순간부터 하단 AI 버튼이 눈에 들어오는지. Agent 가 상품 문맥을 이미 알고 있다는 기대를 심을 수 있는지 |
| 2 옵션 | 스스로 고를 옵션(색·용량·납부·가입·사용자)과 도움이 필요한 옵션(요금제)이 어디서 갈리는지. 절반쯤 고른 상태에서 Agent 를 부르는 타이밍이 자연스러운지 |
| 3 Agent 실행 | 고른 내용이 '옵션 선택중 k/19' 로 이어져 보이는지(문맥 단절). 추천 발화 3개가 지금 상황에 맞는지. 발화 전송 직후 피드백이 기다림을 불안하지 않게 하는지 |
| 4 이용현황·추천 | 내 정보 조회를 먼저 보여주는 순서가 신뢰를 만드는지. 근거·비용·혜택을 한 문단으로 말하는 것이 읽히는지. 이용중 → 추천 카드 캐러셀에서 비교가 되는지, [전체보기] 출구가 자연스러운지 |
| 5 전체 요금제 | 화면 이동 대신 팝업으로 처리하는 것이 맥락 유지에 유리한지. 탭·리스트 정보량이 선택을 끝낼 수준인지, 선택 → 적용 2단계가 과하지 않은지 |
| 6 위약금 질문 | 적용 직후 끼어들기가 입력창·키패드로 자연스럽게 열리는지. 조회 → 결론 → 이어서 할 일 → 근거 순서가 안심과 복귀를 함께 주는지. 다시 나온 요금제 카드가 '아까 본 것' 으로 읽히는지 |
| 7 옵션 ① | 미리 선택 없이 문장 추천 + 직접 탭이 통제감과 속도를 함께 주는지. 섹션이 이어지는 리듬이 읽는 속도와 맞는지 |
| 8 재선택 | 이전 선택(쿠폰)으로 되돌아갈 수 있다는 것이 읽히는지. 되돌아간 뒤 내려오는 동선이 현재 위치를 잃게 하지 않는지 |
| 9 옵션 ② | 완료 안내 + 버튼 하나로 흐름이 닫히는지. 쌓인 대화 길이가 부담스럽지 않은지, 요약이 필요한지 |
| 10 신청서 | 민감 정보를 화면 덮는 시트에서 받는 것이 '입력 모드' 집중과 신뢰를 주는지. n/4 페이저가 부담을 줄이는지. 개인정보 안내를 먼저 보이는 순서가 입력 요청을 받아들이기 쉽게 하는지 |
| 11 주소 | 시트 안에서 내용만 바뀌는 것이 '같은 신청서를 이어 쓰는 중' 으로 읽히는지. 우편번호 검색·5G 지역 체크가 흐름을 끊지 않는지 |
| 12 이메일·연락번호 | 짧은 항목 둘을 시트 두 장으로 나눈 리듬이 지루하지 않은지. 이미 아는 연락번호를 다시 받는 것이 타당한지, Agent 가 채워 두고 확인만 받는 편이 나은지 |
| 13 확인 | 시트 입력이 대화 카드로 돌아와 요약되는 것이 '내가 쓴 게 맞다' 확인을 주는지. '재입력' 링크가 되돌아갈 길로 읽히는지 |
| 14 본인인증 | 인증 수단 선택을 AI 시트로 처리하는 것이 맥락을 유지하는지. 앱 밖으로 나갔다 돌아올 때 어디로 돌아왔고 무엇이 끝났는지 바로 읽히는지. 인증이 두 번 이어지는 것이 피로하지 않은지 |
| 15 납부 | 완료 선이 그려질 때 '처리 완료' 가 읽히는지. 기존 정보가 있는 항목에 '유지' 를 추천하는 것이 안심과 속도를 주는지. 결제 시트가 마지막 관문으로 적절한지 |
| 16 결제 | 결제를 외부 화면으로 넘기는 마지막 관문이 자연스러운지. Agent 가 어디까지 책임지고 어디서 손을 놓는지가 읽히는지 |

### 열린 질문
- 스텝 4 두 번째 Opening "요금제 조회중" 은 내 정보 조회가 아니라 경계 사례 — 유지 여부 미정.
- 3→4 전환이 여전히 풀 디졸브(키패드가 먼저 내려가지 않음) — 미결.
- 옵션이 모두 쌓인 뒤 요약이 필요한가 (2안의 결과 말풍선과 비교 포인트).
