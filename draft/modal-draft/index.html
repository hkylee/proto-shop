Idea 2. 모달 형식 통합

유연하게 옵션을 선택할 때와 정형적 태스크를 탈 Case 간의 모달 처리 방식. 질문 → 로딩 → 다음 질문을 같은 모달 표면이 높이만 바꿔 이어가고, 로딩은 답변 영역이 반짝이는 스켈레톤으로 통일한다. 다음 프로세스가 없으면 모달이 입력창 자리로 줄어든다.

정리 — 1/N 이냐, 전부 “생각중” 이냐

모달 컴포넌트는 하나로 통합하고, 진행 표시만 조건부로 두는 것을 권합니다. 로딩 반짝임·높이 트윈·닫기 규칙을 한 벌로 쓰면 정형/비정형을 사용자가 구분해 배울 필요가 없습니다.

  • 정형 태스크(결제·할인·수령처럼 N이 이미 확정)에서는 남은 개수를 보여주는 편이 낫습니다. 모달이 연달아 뜨는 구간에서 “몇 번 더 답하면 끝나는지”가 보이면 중간 이탈이 줄고, 다음 모달이 뜨는 게 예측 가능해집니다.
  • 단, N을 확정할 수 없으면 절대 쓰지 않습니다. Agent 가 도중에 단계를 늘리면 2/3 → 2/5 가 되고, 그 순간 진행 표시가 신뢰를 깎습니다. 이때는 M-2 처럼 카운터 없이 하나씩만.
  • 숫자가 부담스럽다면 M-3 처럼 레일로 같은 정보를 줄 수 있습니다. 정확한 개수 대신 “거의 끝나간다”는 감각만 전달돼 N이 흔들려도 덜 위험합니다.
